# Architecture

TypeSwitch is a SwiftPM macOS 15+ application with an executable product target, a separate controlled test-host executable, and a test target. The app uses SwiftUI for settings and AppKit for its menu bar integration. It has no third-party Swift package dependencies.

## Event and correction flow

`InputMonitor` uses an active session `CGEventTap` so it can consume Esc only when a recent correction is eligible for undo. Other keys normally pass through; a bounded queue briefly holds keyboard events during a correction. It observes mouse-down and scroll events only to invalidate pending corrections; pointer coordinates are not collected. Keyboard-layout data is refreshed on the main actor and passed to the event thread through a lock-protected snapshot. Key-down events receive monotonic sequence numbers when observed, including while held for a rewrite. One `AsyncStream` consumer delivers them to the main actor in order.

`BufferManager` retains the active word and resets on ambiguous transitions such as navigation, paste, or context change. `LayoutMapper` converts physical keyboard mappings between supported English, Russian, and Ukrainian sources. `LayoutInferenceEngine` combines that mapping with bundled dictionary evidence and refuses ambiguous candidates. `LanguageSwitchEvidenceTracker` handles conservative Russian/Ukrainian language evidence across nearby words.

`RussianInflectionDictionary` also recognizes Russian case forms through bundled Hunspell suffix rules and flagged base entries. It reverses one suffix transformation and requires the original base, its exact affix flag, and the rule's ending condition to match. This covers forms such as `копированием` without guessing endings or storing every expanded word. Known English source words stay protected, and newly recognized Russian forms do not override an ambiguous Ukrainian candidate. Recognition is limited to the bundled rules; irregular forms require explicit dictionary entries. Resources load once per process, with no runtime downloads or learning.

`LayoutCoordinator` orchestrates the flow. `AutoFixFreshnessPolicy` requires the delimiter to remain the latest observed input before a delayed correction can run. `SafetyGateEvaluator` rejects unsafe or unsupported contexts before text mutation.

## Text replacement

`AXFocusedElement` resolves the focused editable control through an injectable Accessibility seam. `AXRewriteEngine` performs and verifies text replacement. Native controls and browser controls have different write policies; browser fields must not receive a speculative whole-value replacement.

`AXRewriteRoutingPolicy` routes known browser/control cases to the bounded physical-key fallback when their AX text model is unsuitable. `SyntheticTextFallbackRewriteEngine` operates only on the observed dictionary-backed token and delimiter after context checks. Posted replacement events carry a marker that excludes only those events from inference; real input has no suppression window. This path is implemented, but broad real-app safety has not been established by the automated tests.

`RewriteInputQueue` serializes correction admission with the event-tap callback and repeats the input-sequence/focus check immediately before mutation. It holds at most 128 key-down, key-up, and modifier events with a 500 ms deadline during AX replacement, fallback replacement, layout switching, or undo. A private completion event follows replacement events at the same HID injection point. When the session tap observes that fence, it translates held physical keys with the refreshed layout and uses [`CGEvent.tapPostEvent`](https://developer.apple.com/documentation/coregraphics/cgevent/tappostevent(_:)) to forward them downstream in order without recapture. User-data markers include a session identifier so stale completion or timeout signals cannot release a newer queue.

Overflow, timeout, pointer activity, and command/control shortcuts cancel remaining synthetic writes and release held input before subsequent input in the same safe focus. A watchdog posts a timeout signal even if typing stops. Secure-input or focus changes discard held events rather than replaying text into another field. Synthetic key releases still pass after cancellation. Stopping monitoring drains the queue before invalidating the tap. Cancellation cannot roll back an already delivered synthetic edit or cancel an AX call already in progress; those exceptional paths may leave a partial correction and require manual compatibility testing.

The fallback prepares all keyboard events before deleting text. It refuses plans exceeding 128 delete/insert strokes before posting any deletion, removes the former initial 40 ms wait, and checks cancellation between strokes. Each insertion event carries explicit modifier flags and the intended character's Unicode payload, so its case does not depend on the default event translation. Physical key codes remain available for frameworks that translate events themselves. Diagnostics record only case counts and modifier state when investigating case mismatches.

`InputSourceController` tracks enabled macOS sources and switches the future layout after the correction flow. `InputSourceChangeTracker` records successful selections synchronously, so a delayed notification for that same source cannot clear the next word after replay has begun; external source changes still reset the buffer. `AutoCorrectionUndoTracker` holds the most recent verified automatic correction briefly so immediate Esc can restore it in the same focused field. `CorrectionUndoEscapeGate` checks expiry and the AX focus identity before consuming Esc, including its repeat and release events. Other input, clicks, scrolling, app/input-source changes, and expiry invalidate that opportunity. The coordinator repeats freshness and context safety checks before restoring text, preserving the delimiter on both AX and bounded fallback paths.

Focus identity is resolved through the frontmost app's AX element, falling back to its focused window when no field identity is exposed. In that limited model, pointer and navigation events cancel undo; programmatic focus changes within the same window remain a manual compatibility concern.

## Local state and presentation

`PermissionsController` preflights keyboard-listening access and Accessibility trust. Settings and the status menu expose a separate action for each missing permission. Input Monitoring requests use the public `IOHIDRequestAccess(kIOHIDRequestTypeListenEvent)` API to register the request, as [recommended by Apple DTS](https://developer.apple.com/forums/thread/828052). Each action opens its matching System Settings pane through `NSWorkspace`, with a general Privacy & Security fallback. The running app can be revealed in Finder for manual addition if macOS omits it from the list. Returning to TypeSwitch refreshes status; newly confirmed access starts monitoring, and detected revocation stops it and clears pending input state. Permission setup does not reset TCC or grant access automatically.

`AppSettingsStore` stores language preferences and the pause shortcut. `AppPolicyStore` stores ignored-app identities. `LearnedCorrectionStore` persists only user-confirmed mappings. A safe learning candidate is held temporarily in memory and expires without being saved unless the user confirms it.

`CorrectionExceptionStore` persists an exception immediately after a successful user-triggered Esc undo, keyed by the exact spelling and source layout. A failed, refused, or expired undo saves nothing. Exceptions and `AbbreviationDictionary` protect automatic inference and learning suggestions; explicit correction remains available. Esc is the explicit opt-out gesture; there is no additional confirmation or popover. Exceptions survive app restarts, and Settings → Exceptions supports removal.

`AbbreviationDictionary` is the single curated, case-sensitive abbreviation lexicon for both source protection and target recognition, including `USB`, `SD`, and `SDI`. For uppercase input consistent with a known source layout, inference maps the token to the other supported layouts and checks for an exact abbreviation match. Valid source words remain unchanged, including words recognized in either Cyrillic language. Abbreviation targets compete with both abbreviation and ordinary-word matches; multiple target layouts are refused, even when their replacement spelling is identical. Trailing punctuation is preserved. No abbreviations are inferred from length or capitalization alone, and unique abbreviation corrections do not become learning suggestions.

`StatusItemController`, settings views, and the learned-words window expose those capabilities. `DiagnosticsLogger` records redacted decision/control metadata, never the typed token or replacement. See [privacy](privacy.md) for storage and permission details.

## Verification boundaries

Tests exercise mapping, ambiguity, freshness, undo, state persistence, redaction, and rewrite/refusal behavior through test seams. `TypeSwitchTestHost` provides controlled AppKit and SwiftUI editable, secure, and read-only fields for manual checks. The [compatibility matrix](compatibility.md) separates expected classifications from observed results; an expected classification is not a verified result.

The publication contains a reviewed source snapshot with fresh public history. The private development history, local build products, diagnostics, and internal task logs are not part of this repository.
